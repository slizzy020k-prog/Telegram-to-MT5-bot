## Spec Reference — the five upgrades

### Upgrade 1 — Guard premature TP1→TP2 lift and `roles_locked`

- A TP1→TP2 lift driven by ATR proximity (`0.50 × M5_ATR`) requires **≥ 50 % leg progress** (entry→TP1 leg) **or** the position is already BE-locked.
- `roles_locked` must **NOT** be set purely by a pre-BE TP lift while deeper zone limits (L2–L4) are still pending. It is set only when **BE is locked** or **TP1 is cleared**.
- Consequence: a deeper, better zone fill (e.g. L4 at 0.02 lot) must be able to be promoted to `CORE_RUNNER` instead of leaving the worst L1 entry as the runner.
- Consequence: valid "Extend SL" edits (Msg 10181) must not be blocked. `main.py::_forward_only_sl_guard` blocks edits when `roles_locked` is truthy — a premature `roles_locked` blocks them.

### Upgrade 2 — Harden `ACTION_CLOSE_WORST_HOLD_LAYERS`

- **2a Future-tense chatter:** ignore messages containing future-tense phrasing (`gonna`, `going to`, `soon`, `about to`, `might`, `will soon`). `"I'm gonna go breakeven early and close worst soon"` must never trigger order modification.
- **2b BANK_TP1 targets:** the action must **not** overwrite `BANK_TP1` layers' TP1 targets with TP3. The Dynamic ATR engine exclusively manages runner TP stepping.
- **2c `stops_level` pre-check:** validate `SYMBOL_TRADE_STOPS_LEVEL` **before** moving worst entries to breakeven, so underwater layers never emit retcode `10016`.

### Upgrade 3 — Monotonic TP typo sanitizer (`parser.py`)

- Detect and drop out-of-order provider TP typos so TP1..TP5 is always strictly ordered (`TP1 > TP2 > TP3 > TP4 > TP5` for SELL, ascending for BUY).
- Canonical repro: `3568 → 3555 → 3437 → 3520 → 3500` (SELL) — `3437` breaks the descending order and must be dropped.

### Upgrade 4 — ADAPTIVE ATR scaling on stub-to-zone edits

- When a bare `"Sell xauusd now"` / `"Buy xauusd now"` stub is edited into a full zone with newly populated SL and TP1..TP5, route those levels through `apply_dynamic_atr_sl_tp` (**ADAPTIVE** mode), exactly like a fresh direct signal.

### Upgrade 5 — Progressive ATR trail tightening (`evaluate_dynamic_atr_trailing_stop`)

| Zone | MFE (open profit, $/oz) | Trail multiplier | Floor |
|---|---|---|---|
| STANDARD | `< $10.00` | `1.40 × M5_ATR` | `$2.50` |
| EXTENDED | `>= $10.00` and `< $18.00` | `1.00 × M5_ATR` | `$2.50` |
| HOME_RUN | `>= $18.00` | `0.80 × M5_ATR` | `$2.50` |

- The multiplier only ever **tightens** as MFE grows; the broker SL only ever moves **forward**.
- Rationale: Msg 10196 peaked near `£423.49` and gave back `$9.00+` (90 pips) on the reversal.

### Upgrade 6 — Regression suite + push

Dedicated regression tests reproducing Msg 10180 (stub-to-zone edit, L4→`CORE_RUNNER` promotion, `3437` TP3 typo sanitization, ADAPTIVE scaling on edit) and Msg 10196 (future-tense `"gonna"` chatter ignored, progressive `1.40x → 1.00x → 0.80x` trail tightening). Full `pytest` green, environment checks validated, committed with a release summary, pushed to `origin main`.
